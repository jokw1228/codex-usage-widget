# 아키텍처

## 구성

- `src/main.js`: Electron main process. 창 생성, 단축키, IPC, 사용량 갱신과 설정 적용을 연결한다.
- `src/core/codex-client.js`: Codex 실행 파일 탐색, app-server 프로세스 실행, JSON 요청/응답과 알림 처리를 담당한다.
- `src/core/rate-limits.js`: 사용량 이벤트를 기존 스냅샷에 병합한다.
- `src/core/settings-store.js`: 설정 파일 읽기/쓰기와 기본값 처리를 담당한다.
- `src/core/window-bounds.js`: 기본/최소 크기, 저장된 창 크기 정규화, 가장자리 크기 계산을 담당한다.
- `src/preload.js`: main process와 renderer 사이의 제한된 IPC 브릿지다.
- `src/renderer.js`: 사용량 payload와 설정 payload를 받아 화면에 렌더링한다.
- `src/ui/usage.mjs`: DOM에 의존하지 않는 한도 선택, 기간/시간 표시 함수를 제공한다.
- `src/index.html`: 위젯 DOM 구조다.
- `src/styles.css`: 투명/항상 위 위젯 UI 스타일이다.

## 데이터 흐름

1. Electron main process가 `codex app-server --stdio`를 실행한다.
2. JSON-RPC 형태로 `initialize`를 보낸다.
3. `account/rateLimits/read` 요청으로 전체 사용량 스냅샷을 가져온다.
4. renderer에 `usage:update` 이벤트로 전달한다.
5. renderer는 응답에 포함된 기간에 맞춰 남은 비율과 리셋 시간을 표시한다. 기간이 하나면 게이지도 하나만 표시한다.

한도 목록은 `rateLimitsByLimitId`에서 만들고, 기존 형식인 `rateLimits`는 한도 ID로 중복을 제거해 보완한다. 처음에는 `codex` 기본 한도를 선택하며, 이후 사용자가 선택한 한도 ID를 새로고침 사이에 유지한다. 선택한 한도가 사라지면 기본 한도 또는 남아 있는 첫 한도로 이동한다.

한도가 둘 이상이면 탭을 표시한다. 기본 응답에 주간 기간만 있으면 주간 게이지만 표시하며, 별도 한도는 해당 이름으로 구분한다. 빈 응답은 안내 문구로, 사용률이 누락된 기간은 `--%`로 표시한다. 계정 응답에 없는 ChatGPT 기능의 한도는 추측해서 만들지 않는다.

창 크기는 한도나 탭 전환에 따라 변경하지 않는다. 작은 창에서는 내용 영역을 스크롤하며, 탭과 스크롤바는 창 드래그 대상에서 제외한다.

## 설정 흐름

투명도, 창 위치, 창 크기 설정은 Electron의 `userData` 경로 아래 `settings.json`에 저장한다.

1. main process가 앱 시작 시 설정을 읽는다.
2. BrowserWindow에 `setOpacity`로 투명도를 적용하고, 저장된 창 위치/크기를 복원한다.
3. renderer가 옵션 버튼 클릭 시 카드 뒷면 옵션 화면으로 전환한다.
4. 옵션 화면의 슬라이더 값이 바뀌면 IPC로 main process에 저장 요청을 보낸다.
5. 설정 초기화 버튼은 기본 투명도와 기본 창 크기를 main process에 요청한다.
6. main process가 파일에 저장하고 창 투명도/크기를 즉시 반영한다.

## 갱신 방식

두 방식을 같이 사용한다.

- Polling: 시작 시, 수동 새로고침 시, 그리고 60초마다 전체 스냅샷을 다시 읽는다.
- Event: app-server가 `account/rateLimits/updated` 알림을 보내면 기존 스냅샷에 병합해서 즉시 반영한다.

단일 한도 알림은 해당 ID의 탭 데이터에도 병합한다. 생략된 필드는 유지하지만 명시적으로 `null`이 된 한도나 기간은 제거하여 이전 값이 남지 않게 한다.

이벤트만 믿으면 누락 가능성이 있고, polling만 쓰면 반응이 늦다. 그래서 하이브리드 방식으로 둔다.

새로고침 진행 중에 다른 새로고침 요청이 들어오면 진행 중인 요청을 함께 기다린다. 통신 초기화도 중복 실행하지 않으며, 응답 완료·프로세스 종료 시 요청 타이머를 정리한다.

## 창 이동과 크기 조절

버튼과 입력 요소는 드래그 대상에서 제외한다. 렌더러는 포인터 동작을 IPC로 전달하고, main process가 화면 좌표를 읽어 창에 적용한다.

드래그 시작 시의 위치와 크기를 기준으로 계산하며, 이동 중에는 시작 크기를 유지한다. 크기 조절도 시작 시점의 크기를 기준으로 계산하므로 동일한 포인터 위치가 반복되어도 크기가 누적되지 않는다.

## 검증

- `npm run check`: 소스, 빌드 스크립트, 테스트 파일의 JavaScript 문법을 검사한다.
- `npm test`: Node.js 기본 테스트 러너로 통신 수명 주기, 설정 저장, 한도 선택, 크기 계산을 검사한다. 실제 Codex 계정에 접속하지 않는다.
- 포터블 exe에서 버튼, 드래그, 크기 조절, 옵션 전환은 별도로 직접 확인한다.

## 오류 처리

Codex CLI를 찾지 못하거나 app-server가 응답하지 않으면 게이지 대신 안내 패널을 표시한다.

안내 문구는 사용자가 해야 할 일을 우선 보여준다.

- Codex Desktop 또는 Codex CLI 설치
- 본인 ChatGPT 계정으로 Codex 로그인
