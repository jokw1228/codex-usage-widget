# 아키텍처

## 구성

- `src/main.js`: Electron main process. 위젯 창 생성, 단축키, Codex app-server 프로세스 연결을 담당한다.
- `src/preload.js`: main process와 renderer 사이의 제한된 IPC 브릿지다.
- `src/renderer.js`: 사용량 payload를 받아 화면에 렌더링한다.
- `src/index.html`: 위젯 DOM 구조다.
- `src/styles.css`: 투명/항상 위 위젯 UI 스타일이다.

## 데이터 흐름

1. Electron main process가 `codex app-server --stdio`를 실행한다.
2. JSON-RPC 형태로 `initialize`를 보낸다.
3. `account/rateLimits/read` 요청으로 전체 사용량 스냅샷을 가져온다.
4. renderer에 `usage:update` 이벤트로 전달한다.
5. renderer는 5시간/1주 남은 비율과 리셋 시간을 표시한다.

## 갱신 방식

두 방식을 같이 사용한다.

- Polling: 시작 시, 수동 새로고침 시, 그리고 60초마다 전체 스냅샷을 다시 읽는다.
- Event: app-server가 `account/rateLimits/updated` 알림을 보내면 기존 스냅샷에 병합해서 즉시 반영한다.

이벤트만 믿으면 누락 가능성이 있고, polling만 쓰면 반응이 늦다. 그래서 하이브리드 방식으로 둔다.

## 오류 처리

Codex CLI를 찾지 못하거나 app-server가 응답하지 않으면 게이지 대신 안내 패널을 표시한다.

안내 문구는 사용자가 해야 할 일을 우선 보여준다.

- Codex Desktop 또는 Codex CLI 설치
- 본인 ChatGPT 계정으로 Codex 로그인
